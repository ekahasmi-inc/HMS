Purpose

The Configuration ERD defines how every subscriber customizes the platform without changing code.

Every configurable aspect of the SaaS is represented in the database.

This is the heart of Sukhavasam SaaS.

1. Configuration Philosophy

The application code provides functionality.

The database determines behavior.

Never:

if resort == "ABC":
    do_something()

Always:

Read Configuration

↓

Execute Rules

↓

Render Result

4. Core Configuration Entities
Entity	Purpose
ConfigurationProfile	Root configuration for tenant
BusinessSetting	Operational settings
Theme	Branding
ThemeVariable	Colors, fonts, spacing
FeatureFlag	Enable/disable functionality
Workflow	Business processes
WorkflowStep	Individual workflow stages
DashboardLayout	Dashboard structure
DashboardWidget	Widget definitions
NotificationTemplate	Email/SMS/WhatsApp templates

PricingRule	Revenue management rules

5. ConfigurationProfile

The root entity for tenant configuration.

Relationship:

Tenant

↓

ConfigurationProfile

↓

All Other Configuration

This enables versioning and rollback.

6. Business Settings

Stores operational defaults such as:

Check-in time
Check-out time
GST percentage
Currency
Timezone
Cancellation policy
Booking confirmation policy
Advance payment requirements

Business rules are data, not code.

16. Configuration Inheritance

Configuration is resolved in this order:

System Default

↓

Subscription Plan

↓

Tenant Configuration

↓

User Preference

Later layers override earlier ones.

17. Versioning

Every configuration profile should be versioned.

This enables:

Rollback
Preview before publishing
Safe updates
Audit history
18. Cross-Module Usage

Every business module references the configuration layer instead of embedding its own settings.

Examples:

Booking reads cancellation rules.
Website Builder reads theme variables.
CRM reads communication templates.
Finance reads tax settings.

This keeps business logic centralized.

19. Future Extensions

The configuration engine should be extensible enough to support future additions without schema redesign, including:

Loyalty programs
Membership tiers
OTA-specific rules
Resort-specific plugins
Custom automation
