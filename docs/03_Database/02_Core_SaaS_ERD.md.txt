Purpose

This document defines the database entities that form the foundation of the Sukhavasam SaaS platform.

Every future module depends on these entities.

1. Design Principles

The Core Platform must provide:

Multi-tenancy
Authentication
Authorization
Subscription management
Feature management
Configuration
Theme management
Media management
Audit logging

It must not contain Booking, CRM, PMS, Inventory, Restaurant, or Finance data.

4. Core Tables

The platform foundation consists of nine core entities.

Entity	Purpose
Tenant	Represents one subscribing business
Resort	Hospitality business profile
Domain	Domain and subdomain mapping
Subscription	Active billing relationship
SubscriptionPlan	Commercial plan definition
Module	Functional application modules
Feature	Individual capabilities within modules
Theme	Website/dashboard appearance
Configuration	Tenant-specific settings

These entities should remain small, stable, and reusable.

5. Tenant Domain
Tenant

Represents one subscriber.

A tenant owns:

Resort
Website
Users
Data
Configuration
Subscription

Relationship

Tenant

│

├── Resort

├── Domain

├── Users

├── Subscription

├── Theme

└── Configuration

Business rules:

One tenant has one active resort (v1)
One tenant has one active subscription
One tenant can have multiple users
One tenant can own multiple domains in the future

7. Domain Domain

Purpose

Maps incoming HTTP requests to the correct tenant.

Examples

↓

Tenant A

↓

Tenant B



www.myresort.com

↓

Business Rules

One primary domain
Multiple aliases allowed
SSL status tracked
DNS verification status tracked

19. Shared Base Entity

Nearly every business entity should inherit common fields from a shared abstract base model.

Recommended common fields:

Unique ID
Created timestamp
Updated timestamp
Created by
Updated by
Status
Version number (for optimistic locking if needed)

Tenant-specific tables additionally include a tenant reference.

This keeps models consistent and avoids duplication.

Architectural Improvements Before Django

Looking at your long-term goal of building a Cloudbeds/Odoo-like hospitality platform, I recommend expanding the Platform Core slightly before writing any models.

Instead of 9 core entities, I recommend 15 foundational entities:

Domain	Entity
Tenant	Tenant
Business	Resort
Domain	Domain
Billing	Subscription
Billing	SubscriptionPlan
Licensing	Module
Licensing	Feature
Configuration	Configuration
Branding	Theme
Assets	Media
Localization	Language
Localization	Currency
Localization	TimeZone
Identity	User (relationship only here)
Audit	AuditLog
