Purpose

This document defines the highest level database architecture. It does not list every table or field. Instead, it defines the core domains and how they relate.

1. Master Database Philosophy

The database is designed around three principles:

Multi-tenant by design
Configuration-driven instead of hardcoded
Modular business domains

Every module must satisfy these principles.

19. Cross-Domain Rules

Every business table should inherit common audit fields from a shared base model rather than duplicating them.

Required common fields:

Primary key
Tenant reference (where applicable)
Created timestamp
Updated timestamp
Created by
Updated by
Active/archived status (where applicable)

This provides consistent auditing and simplifies future maintenance.
